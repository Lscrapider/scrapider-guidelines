# Token Optimizer MCP 小规模实测（2026-10-19）

人工阅读的开发者报告，不进入 Skill 自动加载。测试在 2026-10-18 开始，中断后于 2026-10-19 收尾。只在临时目录安装固定版本及运行源码副本，没有修改真实项目、全局配置、Skill 或日常 AGENTS.md，没有安装配套插件、Hook、请求代理，没有提交、推送或创建分支。

**结论：场景说明可以触发自主调用；本次没有验证到 Token 节省，暂不建议接入日常开发。**

- 连续代码审查：MCP 实际调用三次，任务质量通过，但总 Token 从原生的 119,552 增至 251,737（+110.6%）。Agent 主动关闭了缓存和差异模式，取完全文后又用原生命令读取全文获取行号。这是当前场景说明下真实发生的工作流成本，不能解释为差异缓存本身的成本排名。
- 简单定位：MCP 可用组没有调用 MCP，质量通过；完成运行的总 Token 为 51,453，对照为 49,259（+4.5%）。这项只反映可用工具/指引环境下的简单案例，不能当作“实际使用 MCP”的效果。
- 真实 MCP 协议预检发现默认 `smart_read` 漏报语义变化：Python 缩进改变以及字符串内空格改变，均返回 `// No changes`。关闭缓存和差异模式可以取回全文。完整审查中的三次读取恰好绕开了默认路径，不能据此证明默认差异读取安全。

本试验是两个只读代码审查任务，每个完整配对只有一次；不能推广为所有实现、调试、Java 或 ZCode 任务的效果，也不能证明换一段指引后仍有相同结果。

**实际调用为什么没有带来收益。**

r02 的三次 `smart_read` 参数都显式设置了 `diffMode=false`、`enableCache=false`；随后每个阶段又执行了一次 `nl -ba jsonl_partitioner.py`。MCP 全文与原生全文形成重复输入，额外往返又使历史重复计入。没有证据证明缺少行号是唯一原因，也没有把额外分析、答案差异或工具定义成本单独隔离。

因此，本次验证了“只有 MCP + 场景说明也能自主调用”和这段工作流的实际开销；没有验证“Agent 自主使用差异缓存后能省多少”。不能为得到省 Token 的结果而强制原生组低效读取、删掉必要证据，或把完整模式的质量结果移用于默认差异模式。

**默认差异读取的质量问题是直接复现，不是模型评分猜测。**

预检通过原包的真实 stdio MCP 服务调用 `smart_read`，未改包源码：

- 首读返回全文；未变重读返回 `// No changes`，符合预期。
- Python 函数的末尾 `return "deny"` 仅缩进到 `if` 内，`policy(False)` 从 `"deny"` 变为 `None`；MCP 仍返回 `// No changes`。
- `VALUE = "a b"` 改为 `VALUE = "a  b"`，字符串值改变；MCP 仍返回 `// No changes`。
- 普通非空白内容变化能够返回变化；强制完整读取能恢复被漏掉的源码；启动新的 MCP 进程会重新返回全文，跨进程首读控制通过。

已安装 7.5.1 的 `dist/tools/shared/diff-utils.js` 用 `/\s+/g` 统一空白后比较，`smart-read.js` 调用此判断并启用忽略空白的 diff。这解释了观察结果，但本文不把该结论推广到未测试的其他版本。它足以否定“此版本默认差异读取保留所有代码语义”的保证。原始协议响应见 preflight-results.json，Python 实际行为记录见 preflight-behavior.json；复现入口为 reproduce-preflight.mjs。

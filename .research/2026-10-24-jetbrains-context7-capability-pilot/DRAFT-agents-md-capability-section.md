## 改写草案（v2）

```markdown
- Codegraph＋Serena＋原生检索：作为一组能力，用于源码、符号、调用关系和影响范围分析。
  - 先用 Codegraph 做代码、符号和上下文的初始查询，并复用其返回的源码与相关结果（含影响面清单）；配置键全链、接口多实现/装配路由等结构型问题 Codegraph 优势最大。
  - 精确调用点与同名干扰排查：Codegraph 给出调用方文件清单后，用文本检索补齐精确 file:line，再定向阅读调用点上下文确认接收者类型与遮蔽。
  - 字符串锚点（URL、错误码字面量、mock.patch 目标）与跨目录配置：直接用文本检索（Codegraph 对字符串引用不敏感）；构建产物与索引外目录（target/ 等）只用原生 shell 检索核实。
  - Serena 只补 Codegraph 尚未解决的精确符号、引用或语义操作缺口。JetBrains 后端（与宿主直连 JetBrains MCP 同为 IDEA 内置 MCP 服务的客户端路径）仅用于 IDE 独占操作：语义重命名、IDE 内构建与静态诊断、调试器；检索类问题不加此层（两轮 26 臂实测质量无增量，tokens 约 +20%、调用约 +40%，仅字符串锚点场景墙钟占优）。
  - 三方库 API 事实：引入新依赖或使用断代/新版本库时，先查外部文档确认"最新稳定版本 + 与当前框架版本的兼容性"（本地依赖缓存有版本滞后、兼容性矩阵不可逆向），resolve 时核对库坐标防同名混淆；仓库已有先例的日常实施不查外部文档，API 用法可用本地依赖 jar 实证（unzip/javap）。
  - 原生搜索与定向阅读用于文本、配置、文档以及工具未覆盖的证据。
  - 只查询尚未解决的问题；证据足以支持实现或判断时停止。若某项结果不可用或不完整，使用组内其他可用能力和原生检索补足缺口。多工具同时可用时按上述口径直取所需，不为审计以外的普通检索做跨工具交叉复核（实测组合层收益为负）。
```

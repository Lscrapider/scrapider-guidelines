# finance-init: raw

原始模型输出；保留已发现的遗漏和职责混放，不能直接作为合格示例。

这里只保留能力区块；完整私有测试输入与项目业务规则未纳入归档。

## 已选能力与工作流

- **Scrapider Guidelines** — 代码实现与评审规范。
  - **场景**：非简单的 Java/Spring、Python、Vue/TypeScript 或 Android Kotlin/Compose 实现、重构、调试和评审；Android 界面任务按适用的 Android 与 UI 参考执行。
  - **边界**：Codegraph 和 JetBrains 提供代码证据或 IDE 操作；Scrapider 负责工程规范，不承担代码检索或 IDE 操作。
  - **回退**：对应 Scrapider 参考不适用或未覆盖时，沿用项目已有约定及相关语言、框架指导。

- **Codegraph + 本地检索** — 跨文件关系证据。
  - **场景**：项目有可用索引时，依当前宿主的工具约定在代码问题或编辑前先查 Codegraph；尤其用于跨文件调用、业务流、模块依赖和变更影响问题。索引未覆盖或问题已解决时不继续展开。
  - **边界**：Codegraph 负责关系问题；本地检索和读取负责字面量、配置、文档、当前源码和索引未覆盖的证据，普通文件编辑也使用本地工具。JetBrains 负责其适用的 IDE 语义操作。
  - **回退**：索引不可用、过期或不完整时，改用本地搜索和定向读取。

- **JetBrains IDE MCP** — IDE 语义操作与检查。
  - **场景**：目标项目已在 JetBrains IDE 中打开且 MCP 可用时，用于存在绑定歧义或反射引用风险的符号重命名；代码修改后的单文件诊断及 IDE 支持时的增量编译；依赖声明、签名或当前解析版本不明时检查 IDE 解析结果；采用 Scrapider 时对改动文件或明确审查范围执行机械规范检查；尽力按项目样式整理本地编辑后的代码；以及静态证据不足时调试已复现的运行问题。
  - **边界**：Codegraph 处理关系检索，本地工具负责普通源码检索、文件创建和文本编辑；Context7 负责外部版本与兼容性证据，IDE 和本地依赖负责已解析的声明与签名。IDE 检查提供机械反馈，不替代工程评审。
  - **回退**：项目未打开、MCP 操作不可用或超时，就使用本地检索、项目检查和人工复核，并说明缺少的验证证据；格式化失败时在本地完成。

- **Context7** — 外部库版本、兼容性与 API 依据。
  - **场景**：新增或升级依赖（包括 fork 或改名库）时，按项目包坐标核实库身份，并仅采用坐标匹配的资料确认当前稳定版本及与框架版本线的兼容性；版本敏感的 API 问题在仓库用例和本地依赖材料都无法回答后再查询。
  - **边界**：Context7 负责外部版本与兼容性资料；JetBrains IDE 和本地依赖材料负责已解析依赖的声明与签名。
  - **跳过**：仓库已有明确用法的日常实现不需要查询。
  - **回退**：服务不可用或缺少匹配版本证据时查官方库文档；无法确认的事实应在交付中说明，语言层面的正确性仍须由适用的构建或检查验证。

- **原生规划** — 当前宿主内的规划与执行检查。
  - **场景**：多步骤、跨模块、存在依赖或需要协作的任务；局部且直接的改动直接处理。
  - **边界**：主 Agent 维护唯一的任务计划和完成检查；检索、IDE 与工程规范只提供各自职责内的证据或指导，不另建竞争计划。
  - **回退**：没有原生计划界面时，在任务上下文中列出简要阶段和可观察的完成检查。

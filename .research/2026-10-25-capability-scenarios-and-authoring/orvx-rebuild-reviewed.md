## 能力与工作流

- **代码检索 — Codegraph + 原生检索**
  - **场景**：
    - 项目存在适用的 Codegraph 索引，且需要调查跨文件调用流程、模块依赖或变更影响面时，用 Codegraph 获取关系与影响证据。
    - 已知路径、符号名或字面量时，通过原生搜索和定点读取定位；字面量、配置、文档、当前编辑及索引未覆盖的证据继续使用原生检索。
  - **边界**：Codegraph 负责关系问题并返回源码；复用返回内容，避免通过其他工具重复读取同一源码。
  - **跳过**：没有未解决的关系问题时不做宽泛图查询；不为单个任务重建或重复核验索引。
  - **回退**：索引不可用、过期或不完整时，使用原生搜索和定点读取继续，不因此阻塞任务。
- **编码规范 — scrapider-guidelines skill**
  - **场景**：实现、重构、调试或审查本项目 Java / Spring Boot 平台、Python Worker 与 Vue / TypeScript 前端代码。
  - **边界**：Codegraph、JetBrains IDE MCP 等检索或 IDE 工具提供各自范围内的证据；Scrapider Guidelines 提供工程实现与审查指导。项目约定以本文件及各模块 README / AGENTS.md 为准，用户明确指示优先于项目指令，项目指令优先于 skill。
  - **回退**：skill 或相关参考不可用、未覆盖问题时，按项目既有约定和适用的语言、框架规则继续。
- **JetBrains IDE MCP** — IDE 语义操作与检查。
  - **场景**：目标项目已在 IDE 中打开，且调用明确指向该项目时：
    - 对变量、字段、方法、类等代码符号做语义重命名；另行核对反射字符串。
    - 代码改动后检查文件诊断、在支持时执行单文件增量编译，并按项目风格完成格式化。
    - 依赖签名或版本不明确时，检查声明及当前类路径实际解析的版本。
    - 静态证据不足以定位已复现的故障时，用调试器检查运行状态。
  - **边界**：Codegraph 负责关系检索，原生工具负责普通源码检索、文件创建与文本编辑；IDE 和本地依赖确认已安装的声明与签名，Context7 补充上游版本和兼容性资料。
  - **跳过**：符号绑定明确且项目的工具路由允许时，可用原生编辑改名并搜索核对引用。
  - **回退**：项目未打开、操作不可用或超时时，使用原生工具和项目检查，并说明验证缺口；格式化失败时在本地完成。

- **外部依赖文档 — Context7**
  - **场景**：
    - 引入新依赖、升级依赖或采用近期分叉、改名的库时，核实当前稳定版本及其与项目框架版本线的兼容性。
    - 项目示例与本地依赖制品都无法回答版本敏感的 API 问题时，查询对应版本的文档与示例。
  - **边界**：
    - 按目标库坐标核实文档来源，拒绝同名但不同库的结果。
    - IDE 声明和本地依赖产物用于核实已安装签名；项目已声明版本优先于外部文档示例。
    - 语言层面的正确性通过编译核验，文档查询不能替代该检查。
  - **跳过**：仓库已有实现足以支持的日常开发不查询 Context7。
  - **回退**：Context7 不可用、缺少匹配版本证据或解析出的库身份不匹配时，查阅官方库文档，并说明仍未解决的版本事实。

- **规划 — 原生计划 + 执行清单**
  - **场景**：
    - 本地化或可在单次会话完成的工作使用宿主原生规划和执行清单；小而清晰的改动直接执行。
    - 多步骤、需要协调或后续步骤依赖前序结果的任务使用与工作量相称的计划。
    - 将每个计划步骤连接到可观察的完成检查，并依据执行证据更新计划。
  - **边界**：使用宿主原生规划能力和执行清单，保持单一权威任务计划；不叠加其他规划框架来拥有同一计划。
  - **回退**：宿主不提供原生计划界面时，使用简洁的执行步骤与完成检查继续，不因此引入新的规划工具。

# finance-rebuild: raw

原始模型输出；保留已发现的遗漏和职责混放，不能直接作为合格示例。

这里只保留能力区块；完整私有测试输入与项目业务规则未纳入归档。

## Skill / Tool 分工

- **Superpowers**：任务拆解与流程编排。
    - **场景**：
        - 多步骤任务需要任务拆解或流程协调，按任务组织方案设计、实现、调试、审查、验证及必要的多 agent 协作。
        - 整页、跨页面或全 App 视觉体系任务，需要先澄清目标、范围和成功标准。
    - **边界**：负责规划与流程协调；编码规范由 Scrapider 和项目规则负责，UI 专项职责由对应能力承担。
    - **跳过**：局部简单任务直接处理；Sol 和 Astra 模型不使用；拆解与任务复杂度相称，不为使用流程而扩大范围或过度推理。
- **Apple Design**：Android UI 体验方案。
    - **场景**：
        - 为整页、跨页面或全 App UI 设计体验方案。
        - 处理手势驱动、动效聚焦或空间交互的 Android UI 设计。
    - **边界**：交互与动效方案受 Android 平台和项目视觉系统约束；视觉精修由 impeccable 负责，Compose 实现由 Compose Expert 负责。
    - **跳过**：不用于复刻 iOS。
- **impeccable**：Android UI 设计评审与视觉精修。
    - **场景**：
        - 编码前评审信息架构、视觉主次和视觉语言。
        - 实现后精修界面密度、排版、色彩、状态反馈和无障碍。
    - **边界**：在项目既有视觉系统和已确认的交互方案内精修；体验方案由 Apple Design 负责，Compose 实现由 Compose Expert 负责。
- **Compose Expert**：Android Compose 实现与工程审查。
    - **场景**：
        - 编写、重构、调试或审查 Compose API、代码和 UI。
        - 处理 Compose / Material 3、已批准局部 UI 库、主题、状态、性能、Navigation、Paging、无障碍或 design-to-compose 问题。
        - 审查 Compose PR 或 diff 时使用其 Review Mode。
    - **边界**：Compose 专项由 Compose Expert 负责；更广泛的编码规范由 Scrapider 和项目规则负责，视觉方向由 Apple Design / impeccable 负责。
    - **跳过**：不主导视觉风格。
    - **回退**：能力不可用时按本文件的 Android / Compose 约束和现有实现继续。
- **product-design**：视觉方向对比与真实界面、页面流评估。
    - **场景**：
        - 比较产品的视觉方向。
        - 评估真实产品界面、Android 截图、页面序列或用户流程。
        - 在已选的完整 Compose 设计组合中，用真实截图、页面序列或获准的流程证据指导原生界面精修或忠实实现。
    - **边界**：提供基于界面和流程证据的评估，不决定产品视觉身份，不取代 Apple Design 的交互方案、impeccable 的视觉精修或 Compose Expert 的实现。
    - **跳过**：没有真实界面或流程证据时，不做基于证据的界面或流程评估。
    - **回退**：证据不完整时保留未知行为，说明证据缺口，不据此推断未观察到的行为。
- **scrapider-guidelines**：编码实现、重构、调试与审查规范。
    - **场景**：
        - 执行非 trivial 代码实现任务（CLAUDE.md 明确要求）。
        - 在已选用 Scrapider 编码规范的后端、数据或通用应用代码中进行实现、重构、调试或审查。
    - **边界**：负责工程决策和代码审查，不决定视觉方向；代码事实由 Codegraph / 原生检索提供，现有项目契约和明确任务要求仍然优先。
    - **回退**：具体 Scrapider 参考不适用或未回答问题时，遵循本项目及相关语言、框架规范。
- **Codegraph（MCP）**：代码关系与影响分析。
    - **场景**：
        - 分析反复出现或未解决的跨文件调用链、功能流转、依赖关系和影响范围，且当前主机提供相关 Codegraph 操作、适用索引覆盖相关源码。
    - **边界**：Codegraph 提供关系证据；原生检索和定点阅读处理字面量、配置、文档、当前编辑、直接源码和索引外证据。JetBrains MCP 负责 IDE 语义编辑与 IDE 检查。
    - **跳过**：没有关系问题时不做宽泛图查询；目标已知且无需追踪关系时直接阅读目标，不为每个任务重建或反复检查索引。
    - **回退**：索引不可用、过期或不完整时，用原生检索补足实际缺口。
- **JetBrains MCP**：已打开项目中的 IDE 语义编辑与检查。
    - **场景**：在明确打开于 JetBrains IDE 的目标项目中，按需用于以下任务；每次操作都限定该项目：
        - 重命名变量、字段、方法、类或其他代码符号；绑定关系有歧义或可能涉及反射字符串时尤其适用，并单独核对反射字符串。
        - 代码变更后的单文件诊断。
        - 编辑后的编译验证；IDE 支持时采用单文件增量构建。
        - 依赖版本或签名有歧义时，查看当前 classpath 上已解析的第三方声明和依赖版本。
        - Scrapider 是编码规范时，对改动文件或明确要求的审查范围运行机械规范检查。
        - 原生编辑后按项目格式约定尽力执行 IDE 格式化。
        - 已复现故障且静态证据不足以确定运行时状态或原因时调试。
    - **边界**：普通源码调查由 Codegraph / 原生检索负责，普通文件创建和编辑由原生工具负责；IDE 检查提供机械反馈，不代替标准或语义判断；已解析依赖事实与 Context7 的外部版本、兼容性证据分开。
    - **回退**：项目未在 IDE 打开、操作不可用或调用超时时，改用原生工具和项目已有检查并说明验证缺口；格式化失败时在本地完成。
- **Context7**：外部库版本、兼容性与 API 事实。
    - **场景**：
        - 引入新依赖、采用 fork 或重命名库、升级依赖时，确认当前稳定版本及其与项目框架线的兼容性。
        - 仓库示例和本地依赖工件仍无法回答版本敏感 API 问题时查询外部资料。
    - **边界**：Context7 仅提供经 Maven / npm 坐标核对的外部版本和兼容性证据；已解析依赖签名由 IDE 声明或本地工件确认，项目已声明版本优先于外部示例。
    - **跳过**：仓库示例已覆盖的日常实现不重复查询。
    - **回退**：服务不可用或缺少匹配版本证据时查阅官方文档，并说明未解决的事实。
- **image generator**：缺失视觉资产时的生成能力。
    - **场景**：所需视觉资产缺失，且用户已明确授权生成。
    - **边界**：仅提供缺失的栅格资产；产品视觉身份和资产使用仍由现有设计系统约束，不代替 UI 设计或编码规范。
    - **跳过**：能复用已有合法资源或已批准组件库图标时不使用。
    - **回退**：复用获准资源，或将资产需求留待用户处理，不自动生成替代品。

# Capability descriptions and authoring validation

日期：2026-10-25。正式 skill 使用英文，实验记录可使用中文。本次没有 Git 提交、暂存、推送、分支创建或新增单元测试。

## 最终描述规则

- 每项实际能力各自成条；组合场景内仍保留同级能力条目。
- 场景写可判定的使用任务；边界交代职责交集；跳过只补充额外排除；回退处理不可用或证据冲突。字段不重复，空字段可省。
- 不以字数或行数压缩必要场景。原生搜索、读取和普通编辑是默认或退化路径，不独立包装成工具。
- 主 Agent 的 JetBrains 条目保留六类场景：符号重命名、文件诊断、单文件增量编译、依赖声明和解析版本、格式化、运行时调试。
- inspection 库由 standards-reviewer 定义内部加载、执行和复核。项目能力条目不承载这一内部流程。
- Context7 保留依赖选择/升级和本地证据不足的版本敏感 API 两类场景，以及库身份、声明版本优先、编译验证三项护栏。

## 测试方法与限制

使用 ORVX 和 financial-management-ai 的文档、依赖清单快照，分别执行 init 与 rebuild。输入分别为 32 和 83 个文件；不复制凭据或业务源码。init 无根级 AGENTS.md；rebuild 使用原根文件，仅改能力区块。两个模式均保留已有子目录规则。

初轮使用独立上下文，后续修改后的回归复用了执行 Agent 的历史，因此不作为多次独立样本统计。一次独立 CLI 尝试因账号不支持所选模型而未生成结果。旧临时目录中一轮 finance 输入缺失，原因未确认，该轮作废；最终四个快照重新复制后逐项验证输入完整且未改变。

最终保存了原始生成稿和主 Agent 复核稿。原始稿仍有 Context7 护栏省略或分散的问题；当时还将 inspection 放入主 Agent 的 IDE 条目。复核先集中护栏，再按最新用户要求把 inspection 留给 reviewer，保留其余六类 IDE 场景。最终结果是“复核后的四份文档通过”，不是“一次生成四份均无缺陷”。最后一次职责调整做了文本和路由复核，没有重新声称完成四次独立生成。

# orvx-init: raw

原始模型输出；保留已发现的遗漏和职责混放，不能直接作为合格示例。

这里只保留能力区块；完整私有测试输入与项目业务规则未纳入归档。

## 能力与工作流

- **Scrapider Guidelines** — 代码工程规范。
  - **场景**：在本项目约定下实现、重构、调试或审查后端、Worker、前端及其他应用代码。
  - **回退**：技能或适用参考不可用、未覆盖问题时，遵循模块规则及相应语言和框架约定。

- **Codegraph + 原生检索** — 代码关系与影响证据。
  - **场景**：
    - 处理跨文件调用关系、依赖关系或影响范围问题，且 Codegraph 能确认目标项目有适用索引和所需查询能力时使用。
    - 当前宿主的 Codegraph 工具契约要求优先查询时，按该顺序处理代码问题和编辑前取证；已知路径不免除此要求。
  - **边界**：Codegraph 负责跨文件关系证据；原生检索和文件操作负责字面内容、配置、文档、普通编辑以及索引外证据。遵循适用模块指令中已规定的检索流程。
  - **跳过**：没有待解的关系问题时，不做宽泛的图探索。
  - **回退**：索引不存在、过期或覆盖不足时，使用原生检索和定向读取；不自行创建索引。

- **JetBrains IDE MCP** — IDE 语义操作与检查。
  - **场景**：仅在 IDE 已打开本项目、且调用明确指向本项目时，按任务使用对应能力：
    - 重命名代码符号，尤其绑定关系不明确或可能涉及反射引用时，并单独核对反射字符串。
    - 代码改动后检查单文件诊断。
    - 编辑后在 IDE 支持时检查单文件增量编译。
    - 依赖版本或签名有歧义时，确认第三方依赖的声明、签名和当前类路径版本。
    - 以 Scrapider Guidelines 为编码规范时，对改动文件或明确要求的仓库范围执行机械规则检查；将结果作为候选，并人工复核语义规则及未覆盖项。
    - 原生编辑后按项目风格尽力执行 IDE 格式化。
    - 静态证据不足以定位已复现的运行时故障时，检查调试状态。
  - **边界**：Codegraph 负责关系调查；普通文件创建、文本编辑与常规检索使用原生工具；无歧义的符号改名在宿主路由允许时可用原生编辑并扫描引用。IDE 提供类路径上的依赖事实和机械检查结果；Context7 提供上游版本与兼容性资料，工程判断遵循 Scrapider 和项目规则。
  - **跳过**：不用于大文件切片。
  - **回退**：项目未在 IDE 打开、操作不可用或调用超时时，使用原生工具和项目检查，并说明关键检查缺口；格式化失败时在本地完成。

- **Context7** — 外部依赖版本、兼容性与 API 资料。
  - **场景**：
    - 引入或升级依赖，包括 fork 或改名依赖时，核实匹配项目坐标的当前稳定版本及其与项目框架版本线的兼容性。
    - 仓库用法和本地依赖资料都无法回答版本敏感 API 问题时查询。
  - **边界**：Context7 负责上游版本和兼容性证据；IDE 声明及本地依赖产物负责当前类路径的签名事实。以项目已声明版本为准，并核对库身份与项目坐标一致。
  - **跳过**：仓库已有示例且足以回答的日常用法不查询。
  - **回退**：服务不可用或没有匹配版本的证据时查阅官方文档，并说明尚未解决的事实。

- **原生规划与执行清单** — 宿主原生任务规划。
  - **场景**：任务涉及多个步骤、依赖关系或协调，且适用模块规则未指定其他规划流程时，使用宿主原生规划，列出可观察的完成检查并按新证据更新。
  - **跳过**：单模块、路径明确的局部任务直接处理。
  - **回退**：宿主原生规划不可用时，用简短清单组织步骤和检查。

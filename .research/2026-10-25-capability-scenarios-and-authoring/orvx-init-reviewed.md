## 能力与工作流

- **Scrapider Guidelines** — 代码工程规范。
  - **场景**：在本项目约定下实现、重构、调试或审查后端、Worker、前端及其他应用代码。
  - **回退**：技能或适用参考不可用、未覆盖问题时，遵循模块规则及相应语言和框架约定。

- **Codegraph + 原生检索** — 代码关系与影响证据。
  - **场景**：
    - 处理跨文件调用关系、依赖关系或影响范围问题，且 Codegraph 能确认目标项目有适用索引和所需查询能力时使用。
    - 当前宿主的 Codegraph 工具契约要求优先查询时，按该顺序处理代码问题和编辑前取证；已知路径不免除此要求。
  - **边界**：Codegraph 负责跨文件关系证据；原生检索和文件操作负责字面内容、配置、文档、普通编辑以及索引外证据。遵循适用模块指令中已规定的检索流程。
  - **跳过**：没有待解的关系问题时，不做宽泛的图探索。
  - **回退**：索引不存在、过期或覆盖不足时，使用原生检索和定向读取；不自行创建索引。

- **JetBrains IDE MCP** — IDE 语义操作与检查。
  - **场景**：目标项目已在 IDE 中打开，且调用明确指向该项目时：
    - 对变量、字段、方法、类等代码符号做语义重命名；另行核对反射字符串。
    - 代码改动后检查文件诊断、在支持时执行单文件增量编译，并按项目风格完成格式化。
    - 依赖签名或版本不明确时，检查声明及当前类路径实际解析的版本。
    - 静态证据不足以定位已复现的故障时，用调试器检查运行状态。
  - **边界**：Codegraph 负责关系检索，原生工具负责普通源码检索、文件创建与文本编辑；IDE 和本地依赖确认已安装的声明与签名，Context7 补充上游版本和兼容性资料。
  - **跳过**：符号绑定明确且项目的工具路由允许时，可用原生编辑改名并搜索核对引用。
  - **回退**：项目未打开、操作不可用或超时时，使用原生工具和项目检查，并说明验证缺口；格式化失败时在本地完成。

- **Context7** — 外部依赖版本、兼容性与 API 资料。
  - **场景**：
    - 引入或升级依赖，包括 fork 或改名依赖时，核实当前稳定版本及其与项目框架版本线的兼容性。
    - 仓库用法和本地依赖资料都无法回答版本敏感 API 问题时查询。
  - **边界**：
    - 按目标库坐标核实文档来源，拒绝同名但不同库的结果。
    - IDE 声明和本地依赖产物用于核实已安装签名；项目已声明版本优先于外部文档示例。
    - 语言层面的正确性通过编译核验，文档查询不能替代该检查。
  - **跳过**：仓库已有示例且足以回答的日常用法不查询。
  - **回退**：服务不可用或没有匹配版本的证据时查阅官方文档，并说明尚未解决的事实。


- **原生规划与执行清单** — 宿主原生任务规划。
  - **场景**：任务涉及多个步骤、依赖关系或协调，且适用模块规则未指定其他规划流程时，使用宿主原生规划，列出可观察的完成检查并按新证据更新。
  - **跳过**：单模块、路径明确的局部任务直接处理。
  - **回退**：宿主原生规划不可用时，用简短清单组织步骤和检查。
